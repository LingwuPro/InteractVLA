# RoboCasa365 观测闭环技能

先阅读[接口与评价合同](references/runtime-contract.md)。实现位于 `code/work_dirs/robocasa365_agent`，原生策略适配位于 `code/robocasa365_starvla`；路径和服务端点按发布包配置。

## 输入边界

只使用当前多视角 RGB-D、相机标定、机器人自身末端/关节/夹爪/底盘状态、原始公开指令及已执行历史。不得向规划层提供物体真值、隐藏目标、内部成功阈值或演示。恢复器内部核验完整状态不意味着允许规划器读取隐藏数据。

保留完整原始文本，先执行冻结 VLA 基线；可见进展持续时继续原策略，停滞后重新观察并进行有限恢复。关键点来自当前可见区域，表达完整位置、旋转和命令夹爪宽度。候选接受、实测跟踪、物体抓持与整例成功必须区分。

## 闭环控制

执行短段动作后核对实际状态；底盘控制量不是米或弧度，底盘变化后重测手位姿与目标。腕姿选择同时考虑整手净空和自身关节限位，不只看 TCP。关节贴限位不能单独证明停滞原因。

抓取后短抬并检查同一物体随手运动，持续监测夹爪及相对位姿；非零开度不证明抓稳。门板、把手、抽屉与背景分开测量，旋转门按可见门弧、抽屉按可见直线运动复核。释放后检查真实张爪、物体支撑和撤手稳定性。

任务策略见 `references/`：杯与托盘、开关门/抽屉、器具搬运、导航以及组合食材任务。它们提供观测和控制方法，不保证新布局成功；世界坐标、像素、腕分支须重新测量。

## 评价和轨迹恢复

按实验配置固定初态、公开语言、模型、噪声与尝试预算。原生 success 为唯一整例成功判定，终态立即停止。失败、被拒绝候选和直接控制成本都保留，不能将混合恢复归为纯 VLA 效果。

恢复应保持物理状态、Python 任务缓存、公开语言、控制器状态、动作 dtype 和原命令/观测节奏。只重放实际执行前缀，不重新采样模型，不清零预算，不额外 observe 改变状态。动作重放一致与任务成功分别验证；同 seed 或同物理哈希不足以证明完整环境一致。
